# Phase 017: 관리자 대시보드

## 개요

관리자 전용 대시보드를 구축하여 플랫폼의 사용자, 프롬프트, 거래 현황을 실시간으로 파악하고 관리할 수 있는 시스템을 구현했습니다.

## 구현 범위

### 1. 데이터베이스 스키마 변경

**마이그레이션 파일**: `supabase/migrations/006_admin_role.sql`

- `users` 테이블에 `is_admin` boolean 컬럼 추가 (default: false)
- `admin_get_stats()` RPC 함수: 플랫폼 전체 통계 조회 (관리자 전용, SECURITY DEFINER)
  - 전체 사용자수, 프롬프트수, 활성 프롬프트수, 거래수, 리뷰수
  - 유통 포인트 총량, 오늘 가입수, 오늘 거래수
- `admin_update_prompt_status()` RPC 함수: 프롬프트 상태 강제 변경 (관리자 전용)
  - 유효한 상태값 검증 (`ACTIVE`, `SOLD_OUT`, `DELETED`)

### 2. 미들웨어 보호

**파일**: `lib/supabase-middleware.ts`

- `/admin` 경로에 대한 이중 인증 체크
  1. 로그인 여부 확인 (미로그인 시 로그인 페이지 리다이렉트)
  2. `is_admin` 필드 확인 (비관리자 시 홈으로 리다이렉트)
- 기존 보호 라우트에 `/bookmarks`, `/points` 추가

### 3. 관리자 레이아웃

**파일**: `app/admin/layout.tsx`

- 전용 사이드바 네비게이션 (대시보드, 사용자 관리, 프롬프트 관리)
- 관리자 패널 헤더 (Shield 아이콘, 서비스 복귀 링크)
- 반응형 설계: 데스크톱은 사이드바, 모바일은 가로 스크롤 탭
- 활성 메뉴 하이라이트 (빨간/주황 그라데이션 테마)

### 4. 대시보드 개요 페이지

**파일**: `app/admin/page.tsx`

- 8가지 핵심 지표 카드 그리드 (2x4):
  - 전체 사용자, 전체 프롬프트, 활성 프롬프트, 총 거래
  - 총 리뷰, 유통 포인트, 오늘 가입, 오늘 거래
- 최근 가입 사용자 목록 (5건, 닉네임/이메일/등급/포인트)
- 최근 등록 프롬프트 목록 (5건, 제목/판매자/가격/상태)
- 전체 스켈레톤 로딩 상태

### 5. 사용자 관리 페이지

**파일**: `app/admin/users/page.tsx`

- 닉네임/이메일 통합 검색 (ilike 쿼리)
- 정렬 옵션: 가입일순, 포인트순, 판매수순, 구매수순
- 사용자 목록:
  - 아바타, 닉네임, 이메일, 등급 배지
  - 포인트, 판매수, 구매수, 가입일
  - ADMIN 배지 (관리자인 경우)
- 관리자 권한 토글 버튼 (Shield/ShieldOff 아이콘)
- 페이지네이션 (더보기 패턴, PAGE_SIZE=20)
- 스켈레톤 로딩, 빈 상태 처리

### 6. 프롬프트 관리 페이지

**파일**: `app/admin/prompts/page.tsx`

- 제목 검색 (ilike 쿼리)
- 상태 필터: 전체, 활성, 삭제됨, 품절
- 정렬 옵션: 최신순, 판매순, 조회순, 가격순
- 프롬프트 목록:
  - 제목 (상세 페이지 링크), 상태 뱃지
  - 카테고리, 판매자, 등록일
  - 가격, 조회수, 판매수
- 상태 토글 버튼 (활성 <-> 삭제됨)
  - `admin_update_prompt_status` RPC 호출
- 외부 링크로 상세 페이지 새 탭 열기
- 페이지네이션, 스켈레톤 로딩

### 7. 헤더 연동

- 프로필 드롭다운에 `관리자 패널` 링크 추가 (is_admin인 경우만 표시)
- 빨간색 Shield 아이콘으로 시각적 구분

## 타입 변경

- `User` 인터페이스에 `is_admin: boolean` 추가
- `UserInsert`, `UserUpdate`에 `is_admin?: boolean` 추가

## 보안 설계

1. **미들웨어 레벨**: `/admin` 경로 접근 시 DB에서 `is_admin` 확인
2. **RPC 레벨**: 통계 조회, 상태 변경 함수 내부에서 `is_admin` 재검증
3. **이중 검증**: 클라이언트 사이드 우회 방지를 위한 서버 사이드 이중 체크

## 기술적 결정

- 별도 `admin_users` 테이블 대신 `users.is_admin` 컬럼 사용 (단순성 우선)
- RPC 함수에 `SECURITY DEFINER` 적용하여 RLS 우회
- 관리자 UI는 빨간/주황 그라데이션 테마로 일반 서비스와 시각적 구분
